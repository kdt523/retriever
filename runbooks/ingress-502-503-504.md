---
title: Ingress returns 502, 503 or 504
scope: External requests through an Ingress controller (such as ingress-nginx or Traefik) fail with gateway errors while the backend pods may look healthy.
tools: [kubectl get ingress, kubectl describe ingress, kubectl logs ingress controller, kubectl get endpointslices, kubectl get svc]
cautions:
  - Raising proxy timeouts hides slow backends; find out why requests are slow first.
  - Ingress controller config is shared by every app; change per-Ingress annotations, not global config.
related: [service-no-endpoints, readiness-probe-failing, bad-release-5xx, certificate-expiry]
---

The status code tells you which side failed: 503 means no backend, 502 means the backend answered badly or refused, 504 means it answered too slowly.

## Symptoms

- 503 `Service Temporarily Unavailable`; ingress-nginx logs `Service "demo/gateway" does not have any active Endpoint`.
- 502 `Bad Gateway`; logs show `connect() failed (111: Connection refused) while connecting to upstream` or `upstream prematurely closed connection`.
- 504 `Gateway Time-out`; logs show `upstream timed out (110: Connection timed out) while reading response header from upstream`.
- Requests to the Service from inside the cluster may still work.

## Checks

1. Check the Ingress routes: `kubectl describe ingress <name>` shows host, path, backend service and port.
2. Verify the backend Service exists and has ready endpoints: `kubectl get endpointslices -l kubernetes.io/service-name=<svc>`.
3. Compare the Ingress backend port with the Service port, and the Service `targetPort` with the container port.
4. Read the controller logs for the failing host: `kubectl logs -n ingress-nginx deploy/ingress-nginx-controller | grep <host>`.
5. For 504, measure backend latency directly with a port-forward.

## Likely causes

- 503: Service selector matches no ready pods, or the backend Service name is wrong.
- 502: wrong `targetPort`, app listening only on `127.0.0.1`, or pods restarting mid-request.
- 504: slow backend (CPU throttling, slow database) or a proxy read timeout lower than normal request time.
- Protocol mismatch, for example the backend expects HTTPS but the controller sends HTTP.

## Fix

- Fix the Service selector or ports, or roll back the change that broke them.
- Make the app listen on `0.0.0.0`.
- Fix the slowness at the backend; only then raise `nginx.ingress.kubernetes.io/proxy-read-timeout` on that Ingress if needed.
- Set `nginx.ingress.kubernetes.io/backend-protocol: "HTTPS"` for TLS backends.

## Rollback / escalation

Roll back recent Ingress, Service or app changes first. Escalate to the platform team if every Ingress fails, which points at the controller itself.
